# Contract: `src/sim/*` core module

This project has no network API. The interface contract that matters here is
the boundary between the framework-free simulation core (`src/sim/*`) and
both (a) the Svelte UI shell that calls it every animation frame, and (b) the
`vitest` unit tests that exercise it directly with no DOM (constitution
Principle V, FR-031). This document is that contract.

## `src/sim/types.ts`

```ts
export interface Grid {
  readonly width: number;
  readonly height: number;
  readonly cells: Uint8ClampedArray; // length === width * height, row-major
}

export type Tool = 'sand' | 'eraser';
export type BrushSize = 'small' | 'medium' | 'large';
```

## `src/sim/grid.ts`

```ts
export function createGrid(width: number, height: number): Grid;

export function inBounds(grid: Grid, x: number, y: number): boolean;

export function getCell(grid: Grid, x: number, y: number): number; // 0 = empty
export function setCell(grid: Grid, x: number, y: number, value: number): void;

export function clearGrid(grid: Grid): void; // zeroes every cell, in place
```

**Contract**:
- `createGrid` returns a grid fully zeroed (all cells empty).
- `getCell`/`setCell` on out-of-bounds `(x, y)` are no-ops (`getCell` returns
  `0`) — callers (brush, step) rely on this instead of bounds-checking
  everywhere themselves, satisfying FR-009/FR-020 at a single choke point.
- `clearGrid` mutates `cells` in place (no reallocation) and leaves
  `width`/`height` untouched — this is what the 🗑️ control calls (FR-027);
  it must not touch tool/brush-size state (FR-028), which the UI layer owns.

## `src/sim/step.ts`

```ts
export function step(grid: Grid): void;
```

**Contract** (implements FR-006–FR-010, per research.md §4):
- Mutates `grid.cells` in place; allocates nothing (Principle IV).
- For every occupied cell, bottom row upward:
  - if the cell directly below is empty (or the cell is on the bottom row —
    "below" is off-grid, treated as blocked, not empty) → move down;
  - else if below-left and/or below-right (within bounds) is empty → move
    into one such cell, chosen uniformly at random when both qualify;
  - else the grain does not move.
- Never moves a grain outside `[0, width) x [0, height)`, never overwrites an
  already-occupied cell, never duplicates or drops a grain's byte value
  (shade) in the process (FR-009).
- Idempotent on a fully-settled grid (calling `step` again produces no
  changes) — this is the property "sand piles look stable" ultimately rests
  on, and the property SC-002's "no towers > 2 cells" depends on the
  slide rule actually running until no diagonal is available.

## `src/sim/brush.ts`

```ts
export function applyBrush(
  grid: Grid,
  tool: Tool,
  cx: number,
  cy: number,
  radius: number,
  shade: number, // ignored when tool === 'eraser'
): void;

export function applyBrushLine(
  grid: Grid,
  tool: Tool,
  from: { x: number; y: number },
  to: { x: number; y: number },
  radius: number,
  shade: number,
): void;
```

**Contract**:
- `applyBrush` touches every cell `(x, y)` with
  `(x-cx)^2 + (y-cy)^2 <= radius^2`, clipped silently to grid bounds
  (FR-020).
  - `tool === 'sand'`: writes `shade` into cells that are currently empty
    only (FR-018) — never overwrites an occupied cell.
  - `tool === 'eraser'`: zeroes every cell in the footprint, occupied or not
    (FR-019).
- `applyBrushLine` Bresenham-interpolates grid cells between `from` and `to`
  and calls `applyBrush` at each, guaranteeing no gaps along a fast drag
  (FR-014, SC-005). Called once per `pointermove` with the previous and
  current grid position.
- `shade` for the sand tool is generated by the caller (UI layer, via
  `src/sim/shade.ts`) once per placed grain and passed in — `applyBrush`
  itself does not decide shade values, keeping it a pure grid-mutation
  function that unit tests can call with a fixed shade.

## `src/sim/shade.ts`

```ts
export function randomShade(): number; // 1..255, narrow pink range
```

**Contract**: returns a value in the reserved nonzero byte range representing
a pink hue/lightness variant (FR-012, SC-010 — "at least 8 distinguishable
pink shades"); `0` is never returned (`0` means empty, per the Grid data
model).

## Consumers

- `PlayArea.svelte` is the only caller of `step`, `applyBrush`/
  `applyBrushLine`, and `clearGrid` at runtime — it owns the
  `requestAnimationFrame` loop, calls `step(grid)` once per frame, translates
  pointer/touch events to grid coordinates, and re-renders via
  `putImageData` from `grid.cells`.
- `tests/unit/sim/*.test.ts` import `src/sim/*` directly and assert on
  `grid.cells` contents after one or more `step`/`applyBrush` calls, with no
  DOM and no Svelte involved — this is what makes FR-031/SC-009 possible.
